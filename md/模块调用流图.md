# Digital Employee - 模块调用流图

本文档为数字员工 (Digital Employee) 系统最新架构的模块调用流图与组件交互设计规范，涵盖 **前端 (Front)**、**中间件/消息网关 (Middleware / Gateway)**、**业务与数据中心 (Auth / Data)** 以及 **共享契约包 (Backend-Share)** 的完整拓扑结构与调用链路。

关于 `backend-gateway` 与 `backend-data` 的数据流向专门详解，请参阅 [data-gateway详细说明.md](file:///e:/code/digital-employee/md/data-gateway%E8%AF%A6%E7%BB%86%E8%AF%B4%E6%98%8E.md)。

关于系统用户、角色定义、细粒度权限码与鉴权拦截规范，请参阅 [用户角色权限.md](file:///e:/code/digital-employee/md/%E7%94%A8%E6%88%B7%E8%A7%92%E8%89%B2%E6%9D%83%E9%99%90.md)。

## 1. 总体架构拓扑与交互概览

数字员工系统采用高度解耦的微服务与数据隔离架构：

```mermaid
graph TD
    UI[Frontend 管理端 React 19]
    IM[飞书 / 企业微信 IM 平台]
    GW[Middleware: backend-gateway 消息网关 8864]
    AUTH[backend-auth 身份中心 8020]
    DATA[backend-data 数据平台 8010]
    SHARE[backend-share 共享契约与 SDK]

    INFRA_DB[(PostgreSQL)]
    INFRA_CACHE[(Redis)]
    INFRA_MQ[(RabbitMQ)]
    INFRA_OSS[(MinIO)]

    %% 前端交互
    UI -->|Vite Proxy: /backend-auth-api| AUTH
    UI -->|Vite Proxy: /data-platform-api| DATA

    %% 网关与外部平台交互
    IM <-->|Webhook 回调 / API 发送| GW

    %% 网关与后端交互
    GW -->|data-client 消息租约/数据| DATA
    GW -->|auth-utils 鉴权/权限校验| AUTH

    %% 身份中心与数据服务
    AUTH -->|data-client 用户/权限持久化| DATA

    %% 基础设施唯一访问点
    DATA <--> INFRA_DB
    DATA <--> INFRA_CACHE
    DATA <--> INFRA_MQ
    DATA <--> INFRA_OSS

    %% 共享包支撑
    SHARE -.->|SDK 引用| GW
    SHARE -.->|SDK 引用| AUTH
```

### 关键架构约束（硬边界）：
1. **基础设施隔离**：PostgreSQL、Redis、MinIO、RabbitMQ 的驱动与连接仅允许在 `backend-data` 中存在。
2. **数据契约访问**：`backend-gateway` 与 `backend-auth` 必须通过 `backend-share/data-client` HTTP SDK 访问基础设施。
3. **安全与鉴权**：服务间通过 `backend-share/auth-utils` 进行用户上下文解析与权限编码 (`PermissionCode`) 拦截，网关/身份中心通过统一 `API_KEY` 验证内部通讯。

## 2. 前端 (Front) 架构与 API 调用流

前端基于 React 19 + TypeScript + Vite 8 + Ant Design 6 + Axios 构建。

### 2.1 Vite 开发与预览代理流 (Proxy Layer)

```mermaid
flowchart LR
    Browser[浏览器 Browser]
    ViteServer[Vite Dev/Preview Server :5173]
    AuthService[backend-auth Service :8020]
    DataService[backend-data Service :8010]

    Browser -->|/backend-auth-api/*| ViteServer
    Browser -->|/data-platform-api/*| ViteServer

    ViteServer -->|Path Rewrite & Proxy| AuthService
    ViteServer -->|Path Rewrite & Proxy| DataService
```

- **/backend-auth-api**: 重写为 `/` 后代理至 `http://127.0.0.1:8020`，处理登录、注册、用户/角色/权限/菜单编排。
- **/data-platform-api**: 重写为 `/` 后代理至 `http://127.0.0.1:8010`，处理数据条目、仪表盘、机器人底层元数据及系统配置。

### 2.2 前端 HTTP 请求与 Token 认证流

```mermaid
sequenceDiagram
    autonumber
    participant UI as Page Component / Store
    participant Req as Axios Client (authenticated-request)
    participant AuthSession as Auth Session Manager
    participant Backend as Backend Service (8020 / 8010)

    UI->>Req: 发起 API 请求 (如 fetchUserList)
    Req->>AuthSession: 获取当前的 Access Token & Trace Context
    AuthSession-->>Req: 返回 Bearer Token + X-Trace-Id
    Req->>Backend: HTTP Header (Authorization: Bearer <Token>, X-Trace-Id)
    
    alt Token 有效 (200 OK)
        Backend-->>Req: 返回 ApiResponse 信封 (success, data, code)
        Req-->>UI: 解包返回数据
    else Token 过期 (401 Unauthorized)
        Backend-->>Req: 401 Unauthorized
        Req->>AuthSession: 触发 双 Token 刷新机制 (Refresh Token)
        AuthSession->>Backend: POST /backend-auth-api/api/v1/auth/refresh
        alt 刷新成功
            Backend-->>AuthSession: 颁发新 Access Token
            AuthSession-->>Req: 更新本地 Token 存储
            Req->>Backend: 重试原始 API 请求
            Backend-->>Req: 原始请求响应结果
            Req-->>UI: 返回数据
        else 刷新失败 / Refresh Token 失效
            Backend-->>AuthSession: 401 Refresh Failed
            AuthSession->>UI: 清除登录态并重定向至 /login
        end
    end
```

## 3. 中间件 / 消息网关 (Middleware: backend-gateway) 模块流

`backend-gateway`（端口 8864）作为中间件与接入层，负责对外适配 IM 平台（飞书/企业微信），对内对接消息总线与底层数据服务。

### 3.1 模块内部架构

```mermaid
graph TB
    subgraph backend-gateway [backend-gateway 8864]
        API[FastAPI Admin & Webhook Router]
        BM[BotManager 机器人管理器]
        WD[Watchdog 守护线程]
        HUB[Hub 消息集中分发器]
        RELAY[Outbound Relay Loop 异步轮询任务]
        
        subgraph Platforms [IM 平台适配器]
            FS[Feishu Platform Adapter]
            WX[WeChat Platform Adapter]
        end
    end

    IM_EXT[外部 IM 平台: 飞书/企微]
    DATA_SVC[backend-data 服务 :8010]

    %% 流向
    IM_EXT -->|1. Webhook 事件通知| API
    API -->|2. 解包/推入| HUB
    HUB -->|3. 适配处理| FS
    HUB -->|4. 适配处理| WX
    
    BM -->|守护/配置加载| FS
    BM -->|守护/配置加载| WX
    WD -.->|状态探活| BM

    RELAY -->|5. data-client.claim 消息租约| DATA_SVC
    RELAY -->|6. 分发下行消息| HUB
    HUB -->|7. API 推送消息| IM_EXT
    RELAY -->|8. ACK / NACK| DATA_SVC
```

### 3.2 下行消息长轮询与 Relay 机制 (Outbound Relay Pipeline)

网关启动后通过 `lifespan` 开启异步长任务 `_outbound_relay_loop`，从 `backend-data` 长轮询领取消息租约：

```mermaid
sequenceDiagram
    autonumber
    participant Relay as Gateway Relay Loop
    participant DataClient as Share: data-client
    participant DataBackend as backend-data (8010)
    participant MQ as RabbitMQ
    participant Hub as Gateway Hub
    participant Platform as Feishu / WeChat SDK

    loop 持续长轮询 (Long Polling)
        Relay->>DataClient: claim() 请求领取消息
        DataClient->>DataBackend: POST /api/v1/infrastructure/message-bus/claim
        DataBackend->>MQ: 提取 Pending 队列消息并创建 Lease (Receipt ID)
        MQ-->>DataBackend: 返回消息 Payload & Receipt ID
        DataBackend-->>DataClient: 200 OK (Payload, Receipt ID, Trace ID)
        DataClient-->>Relay: 返回 Message Claim
        
        alt 成功领取消息
            Relay->>Hub: consume_outbound_payload(payload)
            Hub->>Platform: 调用 IM SDK 发送消息给终生用户
            alt IM 平台发送成功
                Platform-->>Hub: 发送成功
                Hub-->>Relay: Outbound Success (True)
                Relay->>DataClient: acknowledge(receipt_id)
                DataClient->>DataBackend: POST /api/v1/infrastructure/message-bus/acknowledge
                DataBackend->>MQ: Confirm ACK (删除消息)
            else IM 平台发送失败 / 异常
                Platform-->>Hub: 发送异常
                Hub-->>Relay: Outbound Failed (False)
                Relay->>DataClient: reject(receipt_id)
                DataClient->>DataBackend: POST /api/v1/infrastructure/message-bus/reject
                DataBackend->>MQ: Reject NACK (重新入列或送入死信队列)
            end
        else 无待处理消息 (Empty Claim)
            DataBackend-->>DataClient: 200 OK (Empty)
            DataClient-->>Relay: None
            Relay->>Relay: 保持 Loop 循环
        end
    end
```

## 4. 后端中心服务与共享包调用链路

后端由 `backend-auth`（身份控制面）、`backend-data`（基础设施数据面）以及 `backend-share`（共享 SDK）组成。

### 4.1 服务分层与职责流

```mermaid
graph LR
    subgraph ServiceLayer [服务与控制层]
        AUTH_API[backend-auth :8020]
        GW_API[backend-gateway :8864]
    end

    subgraph ShareLayer [backend-share 依赖包]
        DC[data-client HTTP Client]
        AU[auth-utils Token/Permission]
        AC[api-common Response Envelope]
        NC[nacos-client Config Sync]
        OBS[observability Trace Context]
    end

    subgraph DataLayer [基础设施统一数据层]
        DATA_API[backend-data :8010]
    end

    subgraph InfraLayer [底层物理基础设施]
        PG[(PostgreSQL)]
        RD[(Redis)]
        RMQ[(RabbitMQ)]
        MINIO[(MinIO Storage)]
    end

    %% 关联
    AUTH_API --> DC
    AUTH_API --> AU
    AUTH_API --> AC
    GW_API --> DC
    GW_API --> AU
    GW_API --> OBS

    DC -->|HTTP REST + API Key| DATA_API
    NC -.->|配置下发| ServiceLayer
    NC -.->|配置下发| DATA_API

    DATA_API --> PG
    DATA_API --> RD
    DATA_API --> RMQ
    DATA_API --> MINIO
```

### 4.2 `backend-share` 组件交互说明

- **`data-client`**:
  - 提供 `MessageBusClient` (处理 `ensure_ready`, `claim`, `acknowledge`, `reject`, `publish`)。
  - 提供 `IdentityClient` / `BotDataClient` 等微服务通讯客户端。
  - 自动在请求头注入内部认证凭证 `X-Service-API-Key`。
- **`auth-utils`**:
  - 包含全局权限码枚举 `PermissionCode` (如 `BOT_MANAGE`, `USER_MANAGE`)。
  - 提供 FastAPI 依赖项 `require_permission` 与 JWT Token 解析器。
- **`api-common`**:
  - 定义统一响应格式 `ApiResponse`（`success`, `data`, `message`, `code`）。
  - 统一异常基类 `ApiException` 及内部处理函数。
- **`observability`**:
  - 基于 ContextVar 的 `TraceContext`，在 HTTP 请求头、RabbitMQ 消息 Payload 之间无缝传递分布式 `X-Trace-Id` 与 `X-Span-Id`。

## 5. 核心业务场景端到端调用时序

### 场景一：用户登录与 API 鉴权调用

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户 (User)
    participant Front as Frontend (React)
    participant Auth as backend-auth (:8020)
    participant DataClient as Share: data-client
    participant Data as backend-data (:8010)
    participant DB as PostgreSQL

    User->>Front: 输入用户名密码提交登录
    Front->>Auth: POST /backend-auth-api/api/v1/auth/login
    Auth->>DataClient: 查询用户信息与密码 Hash
    DataClient->>Data: POST /api/v1/identity/users/verify
    Data->>DB: SQL SELECT Query
    DB-->>Data: 用户记录与加密 Password
    Data-->>DataClient: 用户数据
    DataClient-->>Auth: 返回校验结果
    Auth->>Auth: 生成 Access Token & Refresh Token
    Auth-->>Front: 返回 Dual Token & 用户权限列表
    Front->>Front: 存储 Token 到 AuthSession & Zustand Store
    Front-->>User: 登录成功，渲染管理后台界面
```

### 场景二：上行 IM 消息处理流 (Inbound Webhook)

```mermaid
sequenceDiagram
    autonumber
    actor Member as 飞书 / 企微 用户
    participant IM as 飞书/企微 开放平台
    participant GW as backend-gateway (:8864)
    participant Hub as Gateway Hub
    participant DataClient as Share: data-client
    participant Data as backend-data (:8010)
    participant MQ as RabbitMQ Message Bus

    Member->>IM: 在 IM 中给 Bot 发送消息
    IM->>GW: POST /api/v1/feishu/webhook (事件回调)
    GW->>GW: 验签 (Signature Verification) & 事件解包
    GW->>Hub: 交付归一化 Inbound Message
    Hub->>DataClient: publish_inbound_message(msg)
    DataClient->>Data: POST /api/v1/infrastructure/message-bus/publish
    Data->>MQ: 写入 RabbitMQ 消息队列 (inbound_queue)
    Data-->>DataClient: Publish Confirmed
    DataClient-->>GW: OK
    GW-->>IM: 200 OK (回调快速响应)
```
