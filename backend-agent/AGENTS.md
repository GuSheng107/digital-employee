# backend-agent — Agent Runtime 核心（AI / 新人唯一入口）

## 这是什么

企业级 Agent 核心服务的最小 Runtime：单 Agent、LiteLLM 模型网关、显式绑定的 stdio MCP 与本地 Skill。本目录只负责 Runtime 核心，不碰 `backend-gateway` / `backend-data` / `backend-auth` 等其他服务。

技术栈：Python、FastAPI、LiteLLM。一期代码在 `app/`，配置在 `config/`，测试在 `tests/`。

## 铁律（违反任何一条 = 设计跑偏）

1. 依赖方向固定：`API -> Runtime -> Context / Model / Tool / Recorder`；任何模块不得反向依赖 HTTP 或具体 Provider。
2. Runtime 只识别 `ToolSpec / ToolResult` 与 `ModelGateway` 协议，不感知 MCP / Skill / LiteLLM 内部细节。
3. 追加事件日志是会话唯一事实源，不另建"聊天记录表"；Message 只是投影。
4. 一期不引入长期 Memory / 隐式工具筛选 / 并行工具；工具面只能由 `AgentDefinition` 显式绑定。
5. 新增非显然决策前，先看 [决策记录](docs/10-决策记录/10-决策记录.md)，必要时记一条（决策 + 背景 + 来源）。

## AI 阅读指引（省上下文）

1. 先读本文件 + [TODO](docs/00-概览/TODO.md) + [当前状态与路线图](docs/00-概览/当前状态与路线图.md)（约两页，足以定位任务）。
2. 只读与你任务相关的那一份模块文档，不要全量读 docs。
3. 需要"为什么"时读 [决策记录](docs/10-决策记录/10-决策记录.md)（每条含背景与来源）；不要整读 `docs/40-参考研究/参考项目/` 下的源码，那是 vendored 参考源码，按需读指定文件。
4. 动工前看 [文档规范](docs/90-文档规范/文档编写与留存规范.md) 的"沉淀清单"；做完照它回写文档。风格要求：简洁干练。
