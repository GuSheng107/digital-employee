# Agent 核心模块阶段需求

## 文档使用约定

本目录是重构后 `backend-agent` 的核心设计来源。每份文档聚焦一个模块，正常阅读目标约 2,000 token；实现某模块时只读总览和对应模块文档。`legacy-reference` 中的项目只用于识别已验证需求和旧版边界问题，不是新系统的实现基线。

## 阶段 1：最简可用 Agent Runtime

目标是在本地跑通一个可验证的单 Agent 闭环：用户询问天气，模型决定调用已挂载的天气 MCP 工具，Runtime 执行后将结果交回模型并返回自然语言答案。

范围：

- 提供 `AgentDefinition`：固定系统指令、一个模型配置、显式允许的 MCP Server 和 Skill。
- 提供单请求 `AgentRuntime.run()` 与 HTTP 流式接口；具备 trace ID、取消、超时、最大工具循环次数和结构化错误。
- 使用 LiteLLM 实现 `ModelGateway`，统一模型请求、工具调用、流式输出与 usage；首个验收 Provider 为可配置的 OpenAI 兼容端点。
- 支持受信任本地 `SKILL.md` 的指令注入，以及其声明的本地工具；Skill 必须显式绑定到 Agent。
- 支持 `stdio` MCP：启动、工具发现、schema 转换、调用、关闭；MCP Server 也必须显式绑定。
- 工具统一为 `ToolSpec` / `ToolResult`，并记录模型调用和工具调用的最小审计事件。
- 提供天气 MCP 的端到端测试夹具，以及无工具、工具成功、工具超时、模型返回未知工具四类自动化测试。

不做：长期记忆、自动 Skill/MCP 语义筛选、规划/子代理、审批、后台任务、工作流、Redis、向量库、复杂权限和多 Provider 路由。它们的接口只能预留，不能进入一期运行路径。

验收：一次启动后，可选择一个 Agent、发送“北京今天天气怎样”，并在 trace 中看到模型工具请求、天气 MCP 结果和最终回答；异常不会卡住连接或无限循环。

## 阶段 2：会话、治理与可恢复运行

- 会话历史窗口、上下文预算、短摘要和分层长期 Memory；相关记忆按需检索，禁止全量注入。
- Agent / MCP / Skill 的版本、租户与用户范围；工具白名单、参数校验、风险分级、人工审批与脱敏。
- Run / Step / ModelCall / ToolCall 持久化、checkpoint、重试、取消恢复和基础指标。
- MCP 增加 streamable HTTP 等受控传输；Skill 增加签名、版本和隔离执行。
- LiteLLM 增加多 Provider、故障切换、统一限流/重试、成本与预算策略。

验收：会话恢复不超过预算；相关记忆能命中且可审计；高风险动作会停在审批点；一个中断的 Run 可从 checkpoint 恢复。

## 阶段 3：编排与企业能力

- Routing、Fixed Flow、Plan / Todo、Review、Manager-as-Tools 子代理和 ArtifactStore。
- Knowledge/RAG、连接器、异步任务、队列与更完整的权限、审计、评估、可观测体系。
- 按业务压力再引入 PostgreSQL、Redis、Worker 等基础设施，保持 Runtime 领域接口不变。

验收：固定流程可配置、可重试、可回放；子代理过程不污染主 Agent 上下文；指标可定位模型、工具与上下文成本。
