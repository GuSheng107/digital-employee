# 上下文组装（会话与上下文）

> 定位：一期最小上下文规则 + 二期 Memory 演进。对应架构总览中的 Context Builder。

## 一期最小规则

一期不实现长期 Memory，也不引入向量库或 Redis。每个 Run 的模型输入仅由固定 Agent 指令、已绑定 Skill 指令、已绑定工具 schema、调用方显式传入的短消息列表和本轮用户消息组成。Context Builder 是唯一的组装入口，必须输出 token/字符估算和已纳入的片段清单。

消息按稳定到动态排列：系统指令 -> Skill 指令 -> 工具 schema -> 必要历史 -> 当前消息 -> 当前轮工具结果。这样有利于模型前缀缓存，也使工具结果不会污染固定配置。工具返回文本必须有上限；一期不将原始长结果反复注入。

调用方可传入 `conversation_id`，但一期只将其作为 trace 关联字段；是否加载历史由 API 明确传入，避免隐式持久化带来用户串话和不可预测上下文。

## 二期演进

二期新增 `ContextGateway`，把会话窗口、摘要、Memory、Knowledge 和 Artifact 引用分开处理：

- 固定规则和已确认的少量 pinned memory 可每轮注入。
- 用户偏好、事实、决策、任务状态等长期记忆按命名空间和当前意图检索，命中才注入。
- 长对话先摘要，外部知识检索与 Memory 检索独立，长工具结果进入 ArtifactStore，只回灌摘要和引用。
- 每次注入记录条目 ID、来源、命中理由、预算和截断情况；记忆写入走候选、审核、去重和可追溯流程。

这避免旧版把查询扩词、记忆读取和 Prompt 拼接混进运行服务，也避免“所有记忆每轮全量注入”的成本与隐私风险。具体数据模型在二期启动时另写短设计文档；不得反向修改一期 Runtime 循环。
