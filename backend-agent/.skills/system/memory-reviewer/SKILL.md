# Memory Reviewer

## Overview

memory-reviewer reviews JSON memory files and Memory Packs, detects duplicates, conflicts, outdated memory, wrong promotion, excessive length, missing important memory, and produces repair suggestions or patch plans.

The memory library is **globally shared** — a single unique store with no bot-level isolation.

## Related Skills

- **memory-creator**: creates JSON memory from source text (chat, explicit, or document).
- **memory-reader**: reads JSON memory and builds a Memory Pack for agent context.

memory-reviewer sits between them: it reviews what memory-creator writes and what memory-reader reads, ensuring quality and consistency.

## Core Principles

1. The skill reads JSON memory files and Memory Packs.
2. The skill does not read SQLite.
3. The skill does not parse raw documents.
4. The skill does not create memory from raw source text (that is memory-creator's job).
5. The skill does not build Memory Packs (that is memory-reader's job).
6. The skill does not overwrite memory files by default.
7. It produces review reports and patch suggestions first.
8. It uses deterministic checks plus optional LLM review.
9. Current user feedback overrides historical memory.
10. Explicit memory has higher priority than inferred memory.

## Memory Directory

```
.memory/
  rules.json
  profile.json
  explicit.json
  work.json
  documents/{source_id}.json
  timeline/YYYY-MM.json
  inbox.json
  changelog.json
```

### File Responsibilities

| File | Responsibility |
|------|---------------|
| rules.json | Memory usage rules |
| profile.json | Stable long-term user preferences and communication habits |
| explicit.json | User explicitly requested memory; only from chat or explicit input |
| work.json | Work goals, constraints, decisions, architecture notes, business facts |
| documents/{source_id}.json | Cleaned summary of one document source |
| timeline/YYYY-MM.json | Chronological summaries; can be reviewed and consolidated when redundant |
| inbox.json | Uncertain, conflicting, or low-confidence memory candidates |
| changelog.json | Memory update log |

## Review Types

### memory_files
Review JSON memory files for quality issues. Load all files from the memory directory, run deterministic checks, and optionally run LLM review.

### memory_pack
Review a Memory Pack generated by memory-reader. Check whether important memory is missing, whether irrelevant memory is included, whether token budget is exceeded, and whether conflicts are properly warned.

### user_feedback
Convert user correction or deletion request into repair suggestions. Parse user feedback, identify affected memory items, and generate patches.

### scheduled_cleanup
Run retrospective review, merge duplicates, consolidate redundant or fragmented timeline entries, and suggest cleanup. Memory may continue growing; item count or age alone is not a cleanup trigger.

## Quality Dimensions

| Dimension | Description |
|-----------|-------------|
| relevance | Is the memory relevant to current context? |
| accuracy | Is the memory factually correct? |
| freshness | Is the memory up to date? |
| priority | Is the memory in the correct priority tier? |
| conciseness | Is the memory concise without losing important detail? |
| conflict | Does the memory conflict with other memory? |
| promotion correctness | Is the memory in the correct file? |
| token efficiency | Does the memory use tokens efficiently? |
| safety | Does the memory avoid sensitive or harmful content? |

## Priority Order

1. Current user instruction (highest)
2. explicit.json
3. documents related to current request
4. work.json / chat-session memory
5. profile.json
6. recent timeline
7. inbox.json
8. changelog.json

For duplicate cleanup, apply the stricter source tier: explicit/admin-config memory > document memory > chat/session memory. If chat/session memory repeats document or explicit content, delete the lower-tier duplicate. If document memory repeats explicit/admin-config content, delete the document-side duplicate. Never delete explicit/admin-config memory through an automatic patch.

## File Placement Rules

| Content Type | Correct File | Wrong Placement |
|-------------|-------------|-----------------|
| Explicit user request | explicit.json | profile.json, inbox.json |
| Stable long-term preference | profile.json | explicit.json, timeline |
| Work constraint or decision | work.json | profile.json, inbox.json |
| Document summary | documents/{source_id}.json | timeline, inbox |
| Chronological event | timeline/YYYY-MM.json | profile.json, explicit.json |
| Uncertain or conflicting item | inbox.json | explicit.json, profile.json |
| Document input memory | documents/, work.json, timeline | explicit.json, profile.json |

### Hard Constraints

- Document-sourced memory must never appear in explicit.json or profile.json.
- Explicit memory can only come from chat input.
- Conflicting memory should be in inbox.json, not in explicit.json or profile.json.
- Timeline entries may be reviewed during scheduled cleanup, but age alone is not a reason to compress, archive, or delete them.

## Memory Pack Review Rules

- Check whether explicit memory is missing from the pack.
- Check whether relevant work memory is missing.
- Check whether irrelevant timeline or document memory is included.
- Check whether the Memory Pack exceeds token_budget.
- Check whether conflicts are included without warnings.
- Check whether Chinese memory content is preserved.
- Report missing_memory_warnings when important memory is omitted.

## Deterministic Checks

1. **Duplicate detection**: Find repeated or near-identical items across files.
2. **Conflict detection**: Find negation/affirmation conflicts and direct contradictions.
3. **Verbosity check**: Flag content only when it is repetitive or unnecessarily verbose and can be shortened without losing useful information.
4. **Priority check**: Verify memory is in the correct priority file.
5. **File placement check**: Verify memory content matches file responsibility.
6. **Memory Pack token budget check**: Verify the pack stays within budget; if reader reports `needs_more_memory`, distinguish budget omission from a real memory-base gap.
7. **Missing important memory check**: Warn when expected files are empty, missing, or omitted despite being relevant.
8. **User feedback repair check**: Map user corrections to affected memory items.

## Patch Format

memory-reviewer follows an Agent-first repair model:

- The Agent decides the semantic repair from the provided memory files, Memory Pack, answer, and user feedback.
- The mechanical patch applier validates file targets, preserves fields omitted from `new_item`, and writes JSON atomically.
- For `update`, `compress`, and `promote`, `new_item` may contain any subset of `content`, `content_type`, `speed_lookup`, `retrieval`, `source`, `source_id`, and `priority`.
- Rewrite `content` directly when the stored memory is wrong, incomplete, outdated, fragmented, or too verbose. Do not limit review patches to metadata-only edits.
- Use narrow field-only patches when only one field needs repair.

```json
{
  "patch_id": "",
  "target_file": "",
  "action": "add | update | delete | merge | compress | promote | archive",
  "target_section": "",
  "item_id": "",
  "source_ids": [],
  "old_text": "",
  "new_text": "",
  "new_item": {
    "content": "",
    "content_type": "fact",
    "speed_lookup": "keyword1|keyword2|keyword3",
    "retrieval": {"entities": [], "terms": [], "aliases": [], "keywords": []}
  },
  "reason": "",
  "confidence": "high | medium | low",
  "requires_user_confirmation": true
}
```

For content repairs, include the corrected content and any synchronized fields:

```json
{
  "patch_id": "content-1",
  "target_file": "work",
  "action": "update",
  "item_id": "full-item-id",
  "source_ids": [],
  "new_item": {
    "content": "问题: ... | 原因/解决: ...",
    "content_type": "problem_solution",
    "speed_lookup": "关键词1|关键词2|关键词3"
  },
  "reason": "修正错误或不完整的记忆内容",
  "confidence": "high",
  "requires_user_confirmation": false
}
```

For speed_lookup-only repairs, use a narrow update patch and include only the changed field:

```json
{
  "patch_id": "lookup-1",
  "target_file": "explicit",
  "action": "update",
  "item_id": "full-item-id",
  "source_ids": [],
  "new_item": {
    "speed_lookup": "店家|店+|公司介绍|成立时间|零售SaaS|AI平台"
  },
  "reason": "修正速查词以覆盖真实查询词",
  "confidence": "high",
  "requires_user_confirmation": false
}
```

Do not rewrite `content` or `content_type` when the only issue is speed_lookup quality.

## Processing Flow

### memory_files review

```
load_memory_files → parse_json_items → run_deterministic_checks → optional_llm_review → generate_patch_plan → return_result
```

### memory_pack review

```
receive_memory_pack → check_missing_memory → check_token_budget → check_conflict_warnings → check_chinese_preservation → return_result
```

### user_feedback review

```
parse_user_feedback → identify_affected_items → generate_repair_patches → return_result
```

### scheduled_cleanup

```
load_all_memory_files → run_deterministic_checks → review_timeline_consolidation → merge_duplicates → generate_cleanup_patches → return_result
```

## How to Run

This skill is a **system-level skill** that runs through the project's task/tool system. When a user message triggers this skill, the Agent will receive a `review` script tool and call it with CLI arguments.

### Agent 调用方式

**审核记忆文件：**

```
--review-type memory_files --memory-dir .memory
```

**审核 Memory Pack：**

```
--review-type memory_pack --memory-pack "# Memory Pack\n## Explicit Memory\n- ..." --current-message "帮我查项目约束" --token-budget 4000
```

**处理用户纠正：**

```
--review-type user_feedback --user-feedback "不要用REST风格，改用GraphQL" --memory-dir .memory
```

**定时清理：**

```
--review-type scheduled_cleanup --memory-dir .memory
```

**应用补丁（dry run）：**

```
--review-type memory_files --memory-dir .memory --mode dry_run
```

**应用补丁（实际写入）：**

```
--review-type memory_files --memory-dir .memory --mode patch
```

### 参数说明

| 参数 | 必填 | 说明 |
|------|------|------|
| `--review-type` | 是 | `memory_files`, `memory_pack`, `user_feedback`, `scheduled_cleanup` |
| `--memory-dir` | 否 | 记忆目录路径，默认 `.memory` |
| `--memory-pack` | 条件 | Memory Pack 文本（review_type=memory_pack 时必填） |
| `--current-message` | 否 | 当前用户消息 |
| `--agent-answer` | 否 | Agent 回答 |
| `--user-feedback` | 条件 | 用户反馈（review_type=user_feedback 时必填） |
| `--token-budget` | 否 | Token 预算，默认 4000 |
| `--mode` | 否 | `review`, `patch`, `dry_run`，默认 `review` |
| `--model` | 否 | LLM 模型名称（可选） |
| `--base-url` | 否 | LLM API 地址（可选） |

脚本输出 JSON，包含审核结果和补丁建议：
