# Golden Outputs

用于人工检查 `frontend-dev-spec` 在三种模式下的输出结构是否稳定。

## 开发模式

### 样例 1

输入：

“开发模式，帮我在 `src/pages` 下新增一个 `user-manage` 页面模块”

期望输出结构：

1. 明确识别为开发模式
2. 给出推荐目录结构
3. 给出命名建议
4. 说明页面私有 / 全局公共边界
5. 说明选择 `page-module-minimal` 还是 `page-module-full`
6. 给出注意事项和自检清单

### 样例 2

输入：

“这个列表页的 `api`、`types`、`store` 该怎么放？”

期望输出结构：

1. 先判断页面复杂度
2. 再判断能力归属
3. 明确哪些留页面目录、哪些上移全局
4. 若需要模板，指出读取哪套模板

## 重构模式

### 样例 1

输入：

“重构模式，帮我整理 `frontend/src/pages/PageA`，目标是逐步贴近规范文档”

期望输出结构：

1. 明确识别为重构模式
2. 先列当前问题
3. 再按优先级排序
4. 给出渐进式重构顺序
5. 标出风险和是否建议拆成多次提交

### 样例 2

输入：

“把这一页改成页面模块模式，但不要一次性大动”

期望输出结构：

1. 说明这是历史代码渐进收敛
2. 给出 minimal 或 full 的目标结构建议
3. 说明分几步迁移最稳妥
4. 指出高风险变更点

## 评审模式

### 样例 1

输入：

“评审模式，帮我 review 这次前端改动”

期望输出结构：

1. Findings
2. Open Questions / Assumptions
3. 简短总结

附加要求：

- findings 按严重程度排序
- 先说问题，不先讲概览

### 样例 2

输入：

“看看这个 PR 的目录拆分和状态设计有没有问题”

期望输出结构：

1. 明确 review 重点
2. 优先指出 bug、回归和规范冲突
3. 区分新增问题与历史债务
4. 补充缺失测试或文档同步建议
