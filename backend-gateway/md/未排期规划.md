确实如此，网关根本**不需要关心任何“减一”的动作**。因为：

1. **入队队列加一**：是网关自己执行的（`publish` 的时候，网关完全知情）。
2. **出队队列加一**：是 Agent 执行的，但因为网关是这个队列的**唯一消费者**，只要网关从这个队列捞出一条消息，就意味着出队队列刚刚经历了一次 `+1`。

网关只需要在内存里维持两个一念之间就能算好的累加器：


$$\text{全链路在途总数} = \Sigma(\text{网关入队投递数}) - \Sigma(\text{网关出队消费数})$$

这个差值，就是**最纯粹、最精准、完全无任何网络连接开销的物理排队总数**！

# 智能机器人系统四期规划：基于全链路在途计数（In-Flight）的无开销背压流控方案

## 1. 项目概述与核心目标

### 1.1 建设背景

在三期工程成功落地单节点全异步 RabbitMQ 架构后，系统具备了高并发的异步吞吐能力。然而，当线上遭遇突发流量洪峰，或者后端大模型 API 响应变慢时，网关若无节制地放行所有请求，将导致后端算力彻底过载，从而引发系统雪崩。
为了在极端高峰期保护核心业务，四期工程将引入**全链路在途背压流控机制（In-Flight Flow Control）**。本期方案完全抛弃频繁查询 RabbitMQ 状态接口的重型设计，巧妙利用网关对“入队投递”与“出站消费”的天然感知力，在内存中构建零开销、高精准的动态降级红线。

### 1.2 四期核心目标

* **业务分级能力（Leveling）**：为机器人引入 `level` 属性，通过正整数数字化衡量业务优先级（数值越大优先级越高）。
* **零开销在途监控（In-Flight Counting）**：利用“入队自增、出队自减”的内存计数法则，完全取代物理队列深度查询，达到零网络 I/O 开销。
* **分级熔断与快速失败（Fast-Fail）**：当系统总在途消息数超过环境限额（`LIMIT`）时，低 `level` 机器人的消息在网关层直接熔断，原地改写并异步发回“服务器繁忙”通知；高优先级机器人消息依然维持放行。

---

## 2. 流量限额与等级降级设计

### 2.1 内存对称计数数学原理

网关作为系统的唯一入口（入队生产者）与唯一出口（出队消费者），天生掌握了消息生命周期的两端。

* 当网关执行 `mq_client.publish` 成功时，意味着入队队列增加了一台待处理的任务，**内存计数器 `+1**`。
* 当网关通过 `consume_outbound` 捞出 Agent 的回复指令时，意味着系统成功消化了一台任务，**内存计数器 `-1**`。

网关无需监控任何中途状态（如 Agent 什么时候取走消息、大模型算到了哪一步），只要该计数器满足 `in_flight_count >= LIMIT`，即代表全链路（排队中 + 计算中）负载已达饱和，立刻对低优流量执行柔性拦截。

## 3. 核心架构争议点与原因推演 (Controversy & Resolution)

### 🔴 争议点一：为什么采用“本地内存计数”而不是“实时查询 RabbitMQ 长度”？

* **常规方案**：每次消息入站，通过 `declare_queue(passive=True)` 去 RabbitMQ 节点物理查询一次积压数。
* **本期调整**：改用本地内存整型变量 `in_flight_count` 的自增自减。
* **立论原因**：高并发场景下，即便是微秒级的 AMQP 协议级查询，在面对每秒数万次的 Webhook 洪峰时，依然会产生非必要的网络连接开销。更关键的是，RabbitMQ 的队列长度只能反映“尚未被取走的消息”，如果 Agent 配置了预取（Prefetch），消息被瞬时拉取到 Agent 内存中后，RabbitMQ 的真实队列数会误显示为 0。而**本地内存的在途计数涵盖了“排队中 + Agent死磕中”的全生命周期真实负载**，既做到了真正的零开销，其流控防线也更加精准安全。

### 🔴 争议点二：被流控拦截的消息，如何优雅发回通知而不污染架构？

* **争议现状**：当低级别消息被拦截后，网关需要立刻通知用户“服务器繁忙”。如果此时直接在 `process_inbound` 内部调用底层平台的发信 API，会导致核心调度器再次与平台私有接口发生强耦合。
* **解决机制**：原地触发快速失败（Fast-Fail）。中枢拦截后，直接在内存中克隆该 `StandardMessage` 结构，将其 `content` 数组改写为系统预设的“服务器繁忙”文本，然后直接丢给异步出站函数 `process_outbound`。**这使得流控通知能够百分之百复用二期的多模态处理能力和三期的异步非阻塞出站通道，维持了架构的绝对纯净与对称**。

### 4.2 升级全异步 MessageHub 流控卡点 (`src/core/hub.py`)

```python
import json
import asyncio
import os
from loguru import logger
from src.core.schemas import StandardMessage, MessageContent

class MessageHub:
    def __init__(self):
        self.get_bot_func = None
        # 🌟 核心：纯内存单体计数器，记录当前在全链路（排队中+计算中）流转的消息总数
        self.in_flight_count = 0
        
        # 从环境加载静态流控阀值
        self.queue_limit = int(os.getenv("QUEUE_MESSAGE_LIMIT", "100"))
        self.pass_level = int(os.getenv("FLOW_CONTROL_PASS_LEVEL", "50"))

    def register_bot_provider(self, provider_func):
        self.get_bot_func = provider_func

    async def process_inbound(self, msg: StandardMessage):
        """【纯异步入站切面】基于在途计数的无开销背压降级"""
        bot_instance = self.get_bot_func(msg.bot_id)
        if not bot_instance:
            logger.error(f"[HUB-IN] 找不到对应的机器人配置: {msg.bot_id}")
            return
            
        bot_level = getattr(bot_instance, 'level', 50)
        mode = getattr(bot_instance, 'mode', 'test')
        
        if mode == "prod":
            # 🌟 核心流控卡点：如果在途消息数超标，且当前 Bot 等级低于红线，直接熔断
            if self.in_flight_count >= self.queue_limit and bot_level < self.pass_level:
                logger.warning(
                    f"[FLOW-CONTROL] 触发在途动态降级! 当前全系统在途数: {self.in_flight_count} >= 阈值: {self.queue_limit} "
                    f"| 机器人 {msg.bot_id} 等级 {bot_level} 低于红线 -> 执行拦截快速失败"
                )
                # 挂载后台异步发送繁忙 Rejection，绝不阻塞当前的入站流转
                asyncio.create_task(self._send_busy_rejection(msg))
                return  # 🔴 关键：直接强行拦截，拒绝让消息落入 RabbitMQ
            
            # 🌟 正常放行入队：计数器执行自增
            self.in_flight_count += 1
            logger.info(f"[HUB-IN] 消息成功放行入队 | 当前系统总在途数: {self.in_flight_count}")
            
            routing_key = f"msg.inbound.{msg.platform}.{msg.bot_id}"
            payload = msg.model_dump_json()
            try:
                from src.utils.rabbitmq import mq_client
                await mq_client.publish(routing_key, payload)
            except Exception as e:
                logger.error(f"[HUB-IN] MQ 消息投递崩溃 (Bot={msg.bot_id}): {e}")
                # 🌟 容错保护：如果向物理 MQ 投递宣告失败，必须立刻把内存计数器扣减回来！
                if self.in_flight_count > 0:
                    self.in_flight_count -= 1

        elif mode == "test":
            logger.info(f"[HUB-IN] 机器人 {msg.bot_id} (Test模式)，激活内存异步 Mock")
            asyncio.create_task(self._mock_agent_process(msg))

    async def consume_outbound(self, message):
        """【单实例 MQ 消费者回调】从出队队列捞出消息的瞬间，执行计数器自减"""
        async with message.process():
            # 🌟 核心：消息彻底离开耗时链路，计数器执行自减
            if self.in_flight_count > 0:
                self.in_flight_count -= 1
                
            try:
                payload = json.loads(message.body.decode("utf-8"))
                std_msg = StandardMessage(**payload)
                logger.info(f"[HUB-OUT] 从出队队列捕获到 Agent 回复 | 扣减后系统总在途数: {self.in_flight_count}")
                await self.process_outbound(std_msg)
            except Exception as e:
                logger.error(f"[HUB-OUT] 消费出站指令异常: {e}")

    async def process_outbound(self, msg: StandardMessage):
        """【出站总出口】反归一化发送（异步网络 I/O）"""
        bot_instance = self.get_bot_func(msg.bot_id)
        if bot_instance and hasattr(bot_instance, 'adapter'):
            try:
                await bot_instance.adapter.send_message(msg)
            except Exception as e:
                logger.error(f"[HUB-OUT] 消息发送至外部平台失败: {e}")

    async def _send_busy_rejection(self, msg: StandardMessage):
        """🌟 快速失败处理：原地构建标准提示，反向注入出站出口发送，由于未自增，此处也无需自减"""
        reply_msg = msg.model_copy(deep=True)
        reply_msg.content = [
            MessageContent(msg_type="text", text="⚠️ 服务器繁忙，请稍后重试。")
        ]
        await self.process_outbound(reply_msg)

    async def _mock_agent_process(self, msg: StandardMessage):
        """【测试环境】纯异步非阻塞本地业务模拟"""
        await asyncio.sleep(1)
        reply_msg = msg.model_copy(deep=True)
        for item in reply_msg.content:
            if item.msg_type == "text" and item.text:
                item.text = f"【TEST 异步模拟大脑】已收到指令"
        await self.process_outbound(reply_msg)

hub = MessageHub()

```
